# Development

Technical guide for ArtMuse (`museums-eu-atlas`): an English Next.js App Router app (React, TypeScript, Neon Postgres via Drizzle, Vitest, Playwright) deployed on Vercel at https://artmuse.app. The visitor-facing [README](../README.md) carries no technical detail; it all lives here and in the docs listed below.

## Prerequisites

- Node.js 24 (pinned in `.nvmrc`; run `nvm use`). CI uses the same major.
- npm.
- Optional Neon Postgres database for persisted accounts.
- Vercel CLI when deploying to the linked Vercel project.

## First Run

```bash
npm install
npm run dev
```

Open `http://127.0.0.1:5001/`.

Port `5001` remains the default because macOS often reserves `5000`.

`npm run dev` uses Next's webpack dev backend. The current Turbopack dev server can panic while serving the account route, so webpack is the stable local workflow for now.

Override the local port:

```bash
npm run dev -- -H 127.0.0.1 -p 5010
```

## Checks

```bash
npm run lint        # ESLint 10 flat config
npm run typecheck   # next typegen && tsc --noEmit
npm run test        # Vitest
npm run build       # next build
npm run test:e2e    # Playwright
```

`next-env.d.ts` is generated by `next dev`, `next build`, and `next typegen`, and is gitignored as Next.js recommends.

## Environment Variables

App code reads the environment only through `src/lib/env.ts`. It parses `process.env` with a Zod schema on each request, never at import, so `next build` needs no secrets (CI and Preview builds), and a missing or malformed value fails only the request that needs it. Client components may import its build-time `isProductionBuild` flag; the schema is built lazily so Zod stays out of the client bundle. Tooling (`*.config.ts`, `scripts/`) reads `process.env` directly.

Supported variables:

- `APP_PORT` - local Playwright/dev port, default `5001`.
- `DATABASE_URL`, Vercel-provisioned `POSTGRES_URL`, or `POSTGRES_PRISMA_URL` (in that order) - Neon Postgres connection string for Drizzle account persistence.
- `AUTH_SECRET` - signs magic-link and session tokens. Required wherever sign-in is used, local runs included: there is no fallback, so sign-in answers 503 without it. Generate one with `openssl rand -base64 32`.
- `PUBLIC_APP_URL` - optional absolute URL for generated magic links.
- `AUTH_EMAIL_ENABLED` - kill switch; deployments send sign-in email only when it is exactly `true`.
- `RESEND_API_KEY` - optional email delivery.
- `AUTH_EMAIL_FROM` - optional sender address for email delivery.
- `GIT_COMMIT` - optional commit id that `/api/healthz` reports outside Vercel.
- `APP_BASE_URL` - optional Playwright target for an already running app.

Without `DATABASE_URL`, magic-link auth still works locally and the browser session stays in `localStorage`.

Without Resend settings, the magic-link endpoint returns a dev link in the UI.

## Database

### Local

1. Create a Neon project and copy the Postgres connection string into `DATABASE_URL` or `POSTGRES_URL`.
2. Apply the schema:

```bash
npm run db:migrate
```

### Vercel Marketplace Neon

1. Import the repo in Vercel.
2. Connect Neon from **Storage** in the project dashboard.
3. Redeploy. Build-time migrations run automatically when `POSTGRES_URL` is present.

Useful commands:

```bash
npm run db:generate
npm run db:push
npm run db:studio
```

## End-to-end tests

```bash
npx playwright install chromium
npm run test:e2e
APP_BASE_URL=http://127.0.0.1:5001 npm run test:e2e   # against an already running app
```

The account e2e path uses `/account?testUser=e2e@example.com` in development, so the suite can check the signed-in UI without email delivery. Details: [TESTING.md](TESTING.md).

## Deploying (Vercel + Neon)

Pushes to `main` deploy through the Vercel Git integration (project `museums-eu-atlas`, team `aydar-ga-projects`). Production is https://artmuse.app; `museums-eu-atlas.vercel.app` redirects there.

1. Neon is connected through Vercel → Storage, which injects `POSTGRES_URL` / `DATABASE_URL`.
2. The Vercel build (`npm run vercel-build`) runs Drizzle migrations from `drizzle/` before `next build`, so schema changes ship with the deploy. Migrations must be additive.
3. Production needs `AUTH_SECRET` and `PUBLIC_APP_URL`; email sign-in also needs `RESEND_API_KEY` and `AUTH_EMAIL_FROM` (without them, production sign-in answers 503). See [OPERATIONS.md](OPERATIONS.md).

## Non-goals

- No OAuth, MFA, account deletion, or password reset; magic links replace passwords.
- No runtime image hotlinking.
- No Russian product content copied from `museums-tracker-ru`.
